# Transactional app release procedure

Driver/Plant repairs released 17 October 2026. Runtime source commit 76b08bf; documentation may move ahead independently. The canonical working tree intentionally retains an unrelated Plant seed import; never add it to a repair release implicitly.

1. Freeze app/Worker/module/config sources and relevant tests. Run unit tests, the existing CJS pricing/adapter tests in their canonical workspace (they depend on its parent config/scripts), the lane guard and Worker dry-run. Test real transaction concurrency, restart/retry receipts, cancellation eligibility and native browser storage. Use CUA for browser checks. Keep scope/physical-device gaps explicit.
2. Commit only reviewed repairs and push main. If unrelated pending files exist, preserve them and use a clean detached Git worktree of that pushed commit. The guard checks the shared Git repository, clean status and freshly fetched origin/main; arbitrary copies do not qualify.
3. Bind all public assets and Worker modules/config in CUA evidence. Stage a fresh allowlisted artifact with `python3 tools/driver_release_guard.py --browser-evidence /absolute/evidence.json --stage /absolute/fresh-artifact`. This retains all non-browser checks. Generated release-hashes.json is the only additional public artifact. Never publish tests, backups, source Worker files or unpublished seed/catalogue/carrier work.
4. Deploy the reviewed Worker first. Verify the actual public-key CORS GET and OPTIONS responses with the app Origin: exactly one Access-Control-Allow-Origin value. Plant responses already pass through an inner Worker handler; header names must be normalized with Headers.set, never case-sensitive object spread. A 200 API response does not prove browser access. Open /tony and /plant and require Worker live, not Seed preview.
5. For initial ticket indexing, allow old requests to drain for at least 60 seconds. Use the existing authenticated admin GET/POST /admin/ticket-index. Each POST uses the persisted cursor and processes at most 100 records. After unknown reply, GET the authoritative cursor; never force completion. Require complete indexed/scanned counts and compare source content to bounded date reads, including busiest/recent days. Original undated records remain preserved. Subsequent compatible releases retain this complete index.
6. Install only the paired reviewed reader functions while no known HaulTech writer is running; use whole-file/function hashes, atomic replacement and installed-only tests. Do not execute an apply command to test a reader. Verify the exact installed proof GET function and the existing post-change read-only checks. Unsupported terminal browser credential refresh stays disabled.
7. Publish only the staged Pages artifact using its real source commit. Check immutable and stable hosts: exact hashes for all served files, JSON/JS content types, named driver and /plant,/tony routes. Verify _redirects through generated hashes plus actual route behavior. Verify the Worker build contract and CORS in a real browser. Yard release has a separate six-file reviewed artifact and its own persisted queue checks.

## Storage and rollback

PMG_APP_STORE is now authoritative after migration. Do not roll the Worker back to old KV-only code: that can hide accepted SQL work. Keep its namespace and migration. Prefer a reviewed compatible forward repair; PMG_APP_STORE_READ_ONLY can preserve reads/data during a controlled incident. Frontend rollback must remain compatible with this backend and must preserve local pending queues/journals. Never clear user app storage as a fix.

Driver and Yard updates defer while a form/queue/capture is active. Plant announces an update without automatic reload; reopen it after finishing current work. Offline phones are not proved updated by a successful deployment. Physical Maps/camera/field behavior requires device acceptance; synthetic camera tests do not substitute for that.
